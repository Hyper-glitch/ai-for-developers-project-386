# Границы проекта: один владелец, без авторизации и интеграций

Сервис намеренно ограничен основным сценарием бронирования. Владелец один и задан заранее; авторизации и личных кабинетов нет, поэтому разделы владельца доступны без входа. Интеграций с внешними календарями, видеосвязью и уведомлений нет. Данные допустимо хранить в памяти процесса: перезапуск стирает типы встреч и бронирования, это ограничение указывается в README. Эти «нет» сделаны сознательно, чтобы сосредоточиться на главном сценарии, а не по недосмотру; их не нужно «чинить» без нового решения.
